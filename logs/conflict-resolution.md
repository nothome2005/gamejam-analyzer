# Протокол розв'язання конфлікту людина–агент

## 1. Локалізація конфлікту
- Файл: `spec/system-concept.md`
- Розділ: Базові сутності предметної області (сутність `Submission`).
- Гілки: `human-spec-expansion` (HEAD) та `agent-spec-expansion`.

## 2. Зміст конфліктуючих версій
### Версія кодингового агента (agent-spec-expansion):
Акцент на експлуатаційних параметрах дистрибуції та веб-запуску:
- URL на WebGL-білд (Itch.io / GameJolt)
- Обмеження ваги архіву до 500 МБ
- Ідентифікатор платформи та облік сторонніх асетів

### Версія людини (human-spec-expansion):
Акцент на академічній доброчесності та аудиті сирцевого коду:
- Пряме посилання на Git-репозиторій
- Хеш-сума релізу (SHA-256) для верифікації незмінності коду після дедлайну
- Оцінка оригінальності

## 3. Розмітка конфлікту Git

```text
- Submission (Проєкт): надіслана гра. Обов'язково містить зовнішні URL на WebGL-білд (Itch.io / GameJolt), обмеження ваги архіву до 500 МБ, ідентифікатор цільової платформи та перелік використаних сторонніх асетів.
>>>>>>> agent-spec-expansion
```

## 4. Обґрунтування способу вирішення
Обидва напрямки відповідають призначенню системи аналізу ігрових джемів, оскільки система має обслуговувати одночасно журі (оцінка сирцевого коду) і гравців та організаторів (тестування готових збірок). Автоматичний вибір лише однієї зі сторін знецінює функціональність системи, тому вибір не обґрунтовувався тим, що одна зі змін є новішою, створеною людиною або створеною агентом.

Ухвалено компромісне багаторівневе структурування атрибутів, яке поєднує обидва набори вимог у синтезовану специфікацію.
