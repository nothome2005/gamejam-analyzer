# Реєстр проєктних та ШІ-специфічних ризиків SDD-конвеєра

- **Проєкт**: Інформаційна система обліку та аналізу ігрових джемів (Game Jam Analyzer)
- **Версія документа**: 1.0 (Етап PLAN-GATE)
- **Дата оцінки**: 2026-10-16
- **Цільова система**: Python 3.11+, REST API, SQLite/PostgreSQL, GitHub Actions CI

---

## 1. Загальна матриця класифікації та оцінки ризиків

Шкала оцінки:
- **Ймовірність (L - Likelihood)**: Низька (1), Середня (2), Висока (3).
- **Вплив (I - Impact)**: Незначний (1), Помірний (2), Критичний (3).
- **Рівень ризику (Risk Score = L × I)**: Низький (1–2), Середній (3–4), Високий (6–9).

## 4. Вимоги з посиленим контролем (High Failure Cost)

У системі виділено три критичні вимоги, помилка в реалізації яких завдає непоправної репутаційної чи юридичної шкоди джему:

### 1. REQ-F-003: Цілісність аудиторського сліду та SHA-256 хешу
- **Ціна відмови**: Якщо учасник зможе замінити код гри після дедлайну через невалідний контроль хешу, це зруйнує чесність усього конкурсу.
- **Заходи посиленого контролю**:
  - Окремий тікет безпеки `TICK-FEAT-HASH-01`.
  - Обов'язкове тестування на мутації та спроби підробки хешу (Null-byte injection, регістронезалежність, символи поза `0-9a-f`).
  - Включення обов'язкової ручної перевірки валідатора до чекліста `CORE-GATE`.

### 2. REQ-F-005: Розрахунок запізнень та списання штрафних балів за Soft Deadline
- **Ціна відмови**: Некоректне списання штрафних балів призведе до спотворення результатів лідерборду та неправомірного визначення переможців хакатону.
- **Заходи посиленого контролю**:
  - 100% покриття параметризованими юніт-тестами для всіх часових інтервалів (0 хв, 1 хв, 59 хв, 60 хв, 180 хв).
  - Ізольована верифікація математичної формули штрафу людиною.

### 3. REQ-F-006 / REQ-NF-002: Безпека та ізоляція оцінок на етапі Under Review (RBAC)
- **Ціна відмови**: Витік проміжних оцінок суддів суперникам спричинить скандал, звинувачення в упередженості та зрив суддівства.
- **Заходи посиленого контролю**:
  - Автоматизовані тести проникнення (Penetration security tests) зі спробами виконання API-запитів без токена, з токеном учасника та токеном іншого судді.
  - Обов'язкова перевірка повернення коду HTTP 403 Forbidden з пустим тілом даних.
  - Блокування релізу точкою `RELEASE-GATE` у разі виявлення хоча б одного відкритого ендпоінту оцінок.
